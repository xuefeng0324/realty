# v0.95.0 — 市场流动性 / 挂牌新鲜度（listing-filter mini 卡）

日期：2026-07-25

## 目标

`listing_freshness.csv` 已有 25 行（多城市 × 多小区），每行给出：
- `total_listings`：小区当前挂牌总数
- `recent_4w_count`：近 4 周新增挂牌数
- `new_2w_count`：近 2 周新增挂牌数
- `stale_count`：陈旧挂牌数（一般 ≥ 90 天）
- `freshness_score`：综合鲜活度分（0–100）
- `median_age_days`：小区内挂牌中位天数

这些字段过去**只用于被动查询**（单个 community 详情），dashboard 与 listing-filter 页都没给"市场怎么看流动性 / 哪些小区最近最抢 / 哪些挂牌最积压"的视角。

v0.95.0 把这 25 行派生出 listing-filter 页的「📡 市场流动性」卡：

- 当前城市摘要（小区样本数 + 总挂牌 + 鲜活度均值 + 中位挂牌天数）
- 3 色细分（≤2 周绿 / 2–4 周橙 / 陈旧灰）
- Top 3 最最新鲜小区 + Top 3 最积压小区

派生走 store 已有 `getListingFreshness()` / `getListingFreshnessByCity()`，零抓虫。

## 关键改动

### 1. 新增 `src/local/listingFreshnessRanking.ts`

三个公开函数：

- `summarizeListingFreshnessByCity(cityId?)` → `CityFreshnessSummary[]`
  - 按 cityId 聚合多行（同名城市多条数据合并）
  - 输出：`{ cityId, cityName, communityCount, totalListings, recent4wRate, new2wRate, staleRate, avgFreshness, avgMedianAgeDays }`
  - 默认按 `avgFreshness` 降序

- `getFreshestCommunityTopN(cityId?, n=5)` → 最最新鲜小区
  - 排序：freshnessScore 降序 → medianAgeDays 升序 → totalListings 降序
  - medianAgeDays null 的项**排到最后**（用 `Number.POSITIVE_INFINITY`）

- `getStalestCommunityTopN(cityId?, n=5)` → 最积压小区
  - 排序：freshnessScore 升序 → medianAgeDays 降序 → totalListings 降序

### 2. listing-filter 接入

`src/pages/listing-filter/listing-filter.vue`：

- 新 import：`summarizeListingFreshnessByCity` / `getFreshestCommunityTopN` / `getStalestCommunityTopN` 三个函数 + 两个类型
- 3 个 computed：`freshnessSummary` / `freshestTop` / `stalestTop`
- 新卡「📡 市场流动性」插在"筛选"与"结果"之间（用户进入即可直接看）：
  - 顶部：城市名 + 样本小区数 + 总挂牌 + 鲜活度均值 + 中位挂牌天数
  - **三色细分条**（≤2 周绿 + 2–4 周橙 + 陈旧灰；百分比标签）
  - Top 3：最最新鲜（小区名 + 区，鲜活度值绿）
  - Top 3：最积压（小区名 + 区，中位天数红）
  - 脚注：自解释（派生来源、字段含义）

### 3. CSS

## 设计取舍

| 维度 | 决策 | 理由 |
|------|------|------|
| 进 listing-filter 而非 dashboard | dashboard 已 10+ 张 mini 卡 | listing-filter 是用户"实际去挑房"的页面，"这城市这市场现在是不是好出手"上下文最贴；dashboard 已经饱和 |
| 用 `app.cityId` 同步卡内城市 | listing-filter 顶部筛选已绑定 | 单城市视图与筛选联动，自然 |
| `communityName` 直接拼入 | CSV 已带名称 | 不需要再二次查 school/community 表，减少 import 与索引依赖 |
| 排序字段默认用鲜活度 | 而非陈旧率 | 排在前面的城市是"更鲜"的，dashboard 用户体验正向 |
| 顶部条用纯 CSS flex 而非 canvas | 视觉简洁 | 3 色条仅做宽度对比，不需要交互 |
| `stale - r4` 为负时条会塌 | 容错处理 `(recent4wRate - new2wRate)` ≤ 0 | 数据应不会出现（sub-rate），但容忍即可 |

## 兼容性

- 不破坏 listing-filter 既有"筛选"+"结果"两块主流程
- `freshnessSummary.totalListings = 0`（snapshot 缺 freshness CSV）时整张卡用 `v-if` 隐藏
- `medAgeDays = null` 的积压小区排名也正常（置于末尾 / 显示 — 标签）

## 已知边界

- 仅展示 `app.cityId` 当前城市，未实现"切换到其他城市浏览"。原因：listing-filter 只有当前城市 listings 数据，跨城市对比要切换顶层 `app.cityId`，会触发整个 store 刷新 + listing 列表重建，影响性能。
- `freshness_score` 是综合打分（算法来自 seed 脚本），本派生**不重新打分**，避免双重计算造成数据出口分裂。
- `communityCount` 是按 cityId 聚合的样本小区数；当 freshness CSV 缺某些小区时该数会低于真实小区数。dashboard 脚注已自解释。
