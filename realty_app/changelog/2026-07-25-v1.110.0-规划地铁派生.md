## 背景

`LocalMetroLine` 自 v0.15 起就接入了全链路（types / importer / snapshotLoader /
store），但 0 个派生函数消费它。每行线路已被脚本**预先标注**：

- **4 status**：`规划` / `在建` / `即将开通` / `未知`
- **5 phase**：`深圳四期` / `深圳五期` / `广州三期调整` / `广州四期` / `珠海规划`
- **5 openYear**：2026 ~ 2030（5 年时间线）

地铁规划是**未来感最强**的数据维度——其他 CSV 都是历史/现状，这个直接展示"未来 5 年
新增地铁"。

## 12 个派生函数

| 函数 | 作用 | 价值场景 |
|------|------|----------|
| `summarizeMetroPlanningByCity` | city 聚合：线路数 + 总里程 + 总站数 + status 分布 + 平均最高速 | "深圳 13 条规划线路 vs 广州 5 条" |
| `summarizeMetroPlanningByStatus` | 全国 status 维度 | "全国 16 条在建 vs 4 条即将开通" |
| `summarizeMetroPlanningByOpenYear` | 按开通年份聚合（年升序） | "未来 5 年时间线：2026/2027/2028/2030 各开通几条" |
| `summarizeMetroPlanningByPhase` | phase 维度聚合 | "深圳五期总里程最大（"集中建设期"）" |
| `getMetroPlanningByOpenYear(year)` | 某年开通的全部线路（里程倒序） | "2028 开通线路：深圳 12 条 + 广州 1 条" |
| `getMetroPlanningByStatus(status)` | 某 status 全部线路 | "即将开通的 4 条（最先落地）" |
| `getMetroPlanningByCityTopByLength(cityId, n)` | city 里程 Top N | "深圳在建最长：15 号线 32.2km" |
| `getMetroPlanningByCityTopByStations(cityId, n)` | city 站数 Top N | "深圳站数最多：15 号线 24 站" |
| `getMetroPlanningCrossCityByYear(year)` | 跨城同年开通线路 → `{cityId: lineName[]}` | "2028 三城同时开通对比" |
| `getMetroPlanningByCityFastLines(minSpeed)` | 跨城快线 ≥X km/h | "全国 ≥100km/h 4 条快线（最高 350 珠肇高铁）" |
| `getMetroPlanningByDistrict(name, cityId?)` | 某区覆盖线路 | "南山区通 2 条地铁（深圳 + 广州同名区）" |
| `getMetroPlanningByCityStatusVsStations()` | city × status → 站数总和 | "深圳在建 42 站是最大里程碑" |

## 关键决策

1. **复用预标注**：CSV 已分好 4 status + 5 phase + 5 openYear，避免二次分类漂移。
2. **`null` 默认 0**：lengthKm / stationCount / maxSpeed 都是 nullable，派生时统一
   `?? 0` 处理，避免 NaN 传染排序。
3. **`avgMaxSpeedKmh = 0`**：当 city 所有线路 maxSpeed 都 null 时（如规划早期），返回
   0（而非 NaN）—— caller 可用 `> 0` 安全判断。
4. **`getMetroPlanningByDistrict` 默认跨城**：同名区（如南山区）广州和深圳都有；
   传 cityId 才限定。
5. **`getMetroPlanningByCityStatusVsStations` 排序键 = 站数总和**：UI 用此直接展示
   "city × status 矩阵"，最高站数 = 最强建设力度。
