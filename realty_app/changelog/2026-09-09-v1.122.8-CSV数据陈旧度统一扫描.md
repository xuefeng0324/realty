# v1.122.8 全站 CSV 数据陈旧度统一扫描

## 背景

之前 wangqian 抓取连续 21 天陈旧没人发现——根因是仓库里 41 个 CSV 各自有爬取脚本，
但只在某个 cron 报红时才会被翻；绝大部分陈旧是静默的。本版本提供一个统一视图，
把"哪个数据源多久没更新"集中暴露。

## 改动

- 新增 `realty_app/scripts/check_csv_freshness.py`
  - 扫 `static/*.csv`，按各自表头日期字段（`date` / `publish_date` /
    `as_of_date` / `effective_date` / `year` / `period` / `month` /
    `quarter`）算陈旧天数；
  - 三档分级：OK < 30 天 / WARN 30..60 天 / STALE ≥ 60 天；
  - 退出码：0 / 1 / 2 与等级挂钩，CI 红时邮件告警与 e2e 一致；
  - 输出 markdown 表格 / JSON 给 CI / 人眼；
  - 只依赖 stdlib（csv / datetime / json / argparse），无需 tzdata / pandas，
    不会因 Windows Python 缺 tzdata 崩（修了 `check_stats70_freshness.py`
    同款老问题）。
- 新增 `.github/workflows/check-csv-freshness.yml`
  - 每天 02:30 UTC = 10:30 北京时间（避开 crawl-daily-wangqian 01:30 和 e2e 18:00）；
  - 上传 markdown + json 到 artifact 30 天；
  - 不自动开 issue：避免半夜被批量 issue 轰炸；改成「人在 PR / workflow 摘要里看到」。

## 本次扫描结果（2026-09-09 现状）

- ✅ OK：2 个（`daily_wangqian` 1 天 / `gz_new_house_inventory` 21 天）
- ⚠️ WARN：6 个（多为 NBS / 广东 月度，48~56 天）
- ❗ STALE：35 个（含 stats_70 100 天 / nbs_cpi 62 天 / gd_construction 133 天 /
  gz_provident_annual 531 天 / provident_fund_rates 489 天等）
- 详见 v1.122.7 跑出来的 `freshness.md` / `freshness.json`
