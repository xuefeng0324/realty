# v1.121.5 / v1.121.6 — 启动页 + OTA 根治与验证

## 根因（为何 125「没作用」）

旧 APK（124）检查更新时：

1. `UPDATE_BASE_URL` 指向 `cdn.jsdelivr.net@main`
2. jsDelivr 对 `@main` **长期缓存旧清单**（实测仍返回 121/124），且 HTTP 200
3. 旧逻辑「第一个 200 即采用」→ 误判「已是最新」，**永远不会回退到 raw**
4. 即便偶然拉到新清单，`selectWgtBase` 还把 raw **强制改成 jsDelivr**，而 gcore 上的 wgt 二进制也是脏缓存（sha 对不上）

## 修复（1.121.5）

- 并行拉取多镜像清单，取 **versionCode 最大** 者
- wgt **优先** `raw.githubusercontent.com` / `github.com/.../raw/`（已实测 sha 一致）
- jsDelivr 仅作回退
- 简约暗色启动页（`static/splash/`，写入离线 `drawable/splash.png`）

## 验证包（1.121.6 / 127）

- 关于页文案改为「热更新 127 已生效」
- 整包 APK 使用 **126**（含修复后的 OTA + 新启动页）
- 远程清单发布 **127**，从 126 检查更新应能升到 127

## 真机步骤

1. 安装桌面 `RealtyApp-1.121.5-126.apk`（覆盖）
2. 确认启动页为暗色天际线（不再是 HBuilder 白屏）
3. 设置 → 检查更新 → 应提示 1.121.6（127）
4. 安装并重启 → 关于页显示「热更新 127 已生效」
