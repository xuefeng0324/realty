# v1.122.19 — 修 5 个测试硬断言（v1.122.18 引入的 CI 失败）

**发布日期**：2026-09-09
**versionCode**：298
**versionName**：1.122.19

## 背景

v1.122.18 在 6 个 GD 月度 CSV 各追加 1 行 2026_01_07（publish_date=2026-08-21 / 08-31）。这些 CSV 的 `getLatestXxx()` 用 `sort((a,b) => b.sortKey.localeCompare(a.sortKey))` 字符串比较 `sort_key`（**publish_date 日期字符串**如 `2026-08-21`），所以**新追加行的 sort_key `2026-08-21` > 旧 H1 行的 `2026-07-23`**，最新行从 `2026_H1` 变成 `2026_01_07`。

5 个测试（gd_fa_investment / gd_industrial / gd_real_estate_brief / gd_retail / gd_services）硬断言 `expect(latest!.period).toBe("2026_H1")` —— 一行就 fail 整个 case。本会话的 CI #289 tests / #219 build 因此双红。

## 改动

### 5 个测试文件修改

| 文件 | 改法 |
|------|------|
| `tests/gdIndustrial.test.ts` | period `toBe("2026_H1")` → `toMatch(/^2026(_H1\|_01_0[5-9])$/)`；industryYoyPct / electronicsYoyPct 加 H1 vs 1-7 月二选一 |
| `tests/gdFaInvestment.test.ts` | period regex；faYoyPct → `-11.3`；industryYoyPct / manufacturingYoyPct 加 H1 vs 1-7 月二选一；prYoyPct 加 H1 vs 1-7 月分支（1-7 月简讯无房地产投资字段 = 0） |
| `tests/gdRealEstateBrief.test.ts` | period regex；salesAreaWanSqm / investmentYi 加 H1 vs 1-7 月二选一；trend 顺序断言从 `["H1","01_05","01_04"]` 改为 `["01_07","H1","01_05"]`（1-7 月挤到 trend 头部） |
| `tests/gdRetail.test.ts` | period regex；retailYoyPct / communicationsYoyPct 加 H1 vs 1-7 月二选一；retailTotalYi 分支断言（H1 = 23219.73 / 1-7 月简讯无总额字段 = 0） |
| `tests/gdServices.test.ts` | period `toBe("2026_01_05")` → `toMatch(/^2026_01_0[5-9]$/)`；revenueYoyPct / leasingYoyPct / itYoyPct 加 H1 vs 1-7 月二选一 |

### 根因同 v1.122.14

v1.122.14 修过的是 `month=2026-05/06` 硬编码的**单字段**断言；本会话修的是 `period=2026_H1` 硬编码的**多字段**断言。两者根因一致：**测试把"当前最新"绑死到具体 period 值**，而不是"当前最新必须符合 2026 年累计月份"。**正确做法**：period 用 regex `/^2026(_H1|_01_0[5-9])$/`，数值用 ternary `latest.period === "2026_H1" ? H1值 : 1-7月值`。

## 教训

- **测试断言绝对不能用"最新一行 period 是 X"**——CSV 一追加新行，sortKey 一变就坏。
- period 字段的 regex 永远要包含未来所有可能值（H1 / 01_05 / 01_06 / 01_07 / 01_08 ... / Q1 / Q2 / Q3 / Q4）。
- 数值断言用 ternary 或 `toMatchObject` 模式匹配多套数据，不要 `toBe(specificValue)`。
- 这是**第三次**踩同一个坑（前两次：v1.122.14 month 硬编码、本会话 period 硬编码），必须把"period / sort_key 必用 regex"列入 AGENTS.md 协作纪律。
