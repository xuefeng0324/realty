# v0.78.0 E2E 服务就绪门禁

## 问题

本地启动静态服务器后立即运行历史 E2E 时，首批并行脚本可能早于服务完成监听，从而把启动阶段的连接拒绝误记为浏览器瞬时网络错误。测试最终可以重试通过，但会污染重试统计，也延长反馈时间。

## 改动

- 新增通用 `waitForHttpReady`，轮询测试地址直到返回2xx状态。
- 核心、扩展和历史运行器均在启动第一个 smoke 脚本前执行就绪检测。
- 默认等待30秒，支持通过 `E2E_READY_TIMEOUT_MS` 调整。
- 超时错误包含地址、等待时间、尝试次数和最后一次错误。
- 历史 JSON 报告记录就绪检测状态、耗时和尝试次数。
- 单测覆盖服务恢复和持续不可用场景。

## 技术选择

就绪检测放在套件运行器，而不是每个 smoke 脚本中，保证只等待一次，也避免55个浏览器进程重复探测。仍保留运行过程中的限定瞬时错误重试，用于处理服务已就绪之后的真实网络波动。
