# v1.122.52 e2e visual-diff 阈值 2% → 5%（fix CI 字体差异）

**日期**: 2026-09-13 上午
**head**: 待 commit（已 bump）

## 背景

`realty_app e2e` workflow（每天 18:00 UTC + PR 触发）连续 fail：

- **#70** main schedule FAIL（2026-09-11 20:21 UTC，在我 v1.122.51 commit 之前）
- **#71** dependabot PR FAIL
- **#72** main schedule FAIL（2026-09-12 20:04 UTC，在 OTA 自动 commit 8b543e2 之后）

失败 step 都是 `跑视觉回归（diff vs baseline）`，不是 smoke。baseline 同步护栏 step
**显示 success**——所以 guard 自身有 bug（它比较 SHA，但 run 失败那刻 SHA 实际上不等，
guard 不知为何 success，下次单独排查）。

**根因排查**：
- 本地 build + serve + smoke + visual-diff 完整复现：**本地 diff=0.668% ≤ 2% PASS**
- CI 跑同样的 visual-diff：**FAIL（>2%）**
- 唯一区别：CI runner 字体渲染/抗锯齿与本机 Windows 不同 → PNG 像素级差异
- src/ 自 9-09 dashboard 减负后无 UI 改动，**没有真视觉回归**

**决策**（用户拍板）：把阈值从 **2% 放宽到 5%**，让 CI 字体差异能过、未来真视觉回归也留出 5% buffer。

## 改了什么

| 文件 | 改动 |
|------|------|
| `tests/e2e/visual-diff.mjs` | 默认 `0.01` → `0.05` + 顶部注释同步 |
| `.github/workflows/realty-app-e2e.yml` | 显式 `--threshold 0.02` → `--threshold 0.05` |

## 验证

- 本地 `node tests/e2e/visual-diff.mjs --threshold 0.05`：**diff=0.668% ≤ 5% PASS** ✅
- CI 再跑（明天 18:00 UTC schedule）应能绿

## 警告（诚实记录）

阈值从 2% 放宽到 5% **让真视觉回归也要超过 5% 才报警**——
本地 diff 0.668% 远低，但 5% 是「5 个像素里有 1 个不同」级别的容忍。
后续如果做重大 UI 改动（换色板/布局重排），需要同步更新 baseline，否则会假阳性
通过。建议**重大 UI 改动后立即**本地跑 `node tests/e2e/visual-diff.mjs --update-baseline`
提交新 baseline。

baseline guard step「显示 success 但 SHA 不等」的 bug 暂未修——本轮聚焦让 CI 绿；
guard bug 等下次单测时再排查。
