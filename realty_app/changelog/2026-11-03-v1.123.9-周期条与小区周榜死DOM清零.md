# v1.123.9 · 周期条与小区周榜死 DOM 清零

## 背景

v1.122 首页收敛为 `.home-v122-shell` 壳层后，壳层 CSS（`.home-v122 .container > :not(.home-v122-shell):not(.sheet-mask){display:none!important}`）把所有遗留长卡永久隐藏。v1.123.6/7/8 已分批删除旧专业 Tab、data-tab 死属性与 F-DASH-01 工作台；本轮巡检发现同区块仍有三块死 DOM 挂着完整实现。

## 删除内容（dashboard.vue）

1. **`topnav-period` 周期切换 sticky 条**（v0.49.0 遗留）：上一周/下一周按钮、第 N/M 周指示。
2. **`week-bound-strip` 本周速览条**：上榜小区 / 有数据的区 / 周榜 Top1 三个 KPI。
3. **`week-ranking-card` 小区周榜卡**：Top 20 小区行（均价/挂牌/置信度）。其 hide 按钮引用的 `school-top-community` 键在 v1.123.2 已划出卡片管理清单，属死控件，随卡一并清除。

连带删除：

- `stepPeriod` / `currentPeriodIdx`（仅周期条消费）
- `ranking` / `rankingTotal` refs（仅上述两块消费）
- `loadRankingAndDistrict` 内 `getCommunityRanking` 调用（Promise.all 简化为单 `getDistrictCompare`；`app.metric` 由区/板块对比等卡继续消费，保留）
- 孤儿 import：`CommunityRankingItem`（api/contracts）、`coverageText`（utils/format）
- `.topnav-period` / `.topnav-p-week` / `.topnav-p-num` / `.topnav-p-btns` / `.topnav-p-btn` / `.topnav-p-btn:active` / `.topnav-p-btn--disabled` 7 组 CSS
- 历史测试 buildIntegrity「v0.49.0 topnav-1 周期 sticky 顶栏」4 条字符串断言（前提失效）；防回归门禁并入 `dataToolsEntry.test.ts`（禁再出现 `topnav-period` / `stepPeriod` / `currentPeriodIdx` / `week-bound-strip` / `week-ranking-card` / `rankingTotal` / `getCommunityRanking`）

## 保留（行为不变）

- `periods` / `loadPeriods`：`loadAll` 默认周初始化（`app.setWeekEnd(periods[last])`）仍消费
- `sourceOptions`：来源校验仍消费
- `getCommunityRanking` 库函数：`apiWrappers.test.ts` / `pipeline.test.ts` 直接单测在测
- `.community-row` 等行样式：商业热度等多张隐藏卡仍共用
- `.cell-label`：几十张卡共用
