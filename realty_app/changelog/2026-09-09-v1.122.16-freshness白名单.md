# v1.122.16 (295) — check_csv_freshness.py EXEMPT_FROM_STALE 白名单

## 背景

v1.122.8 引入 `check_csv_freshness.py` 后，cron 每天 02:30 UTC 邮件
告警会把「年度 / 季度 / 月度一次性发布」的源（公积金年报、教育统计、
70 城指数等）一起标 STALE，但**这些源不是脚本失效**，只是 freshness
默认阈值 30 / 60 天对它们的发布节奏不适用。每次 cron 都推 5~12 个
假阳性 STALE，邮件噪音占 90%。

## 改动

`realty_app/scripts/check_csv_freshness.py` 加 `--exempt-from-stale` 参数：
- 逗号分隔的文件名白名单（不带路径）
- 匹配项在 markdown 报告里标记为 `⏸ EXEMPT`，保留陈旧天数便于人眼扫
- **不计入 worst 退出码**（worst=2 不会被它推上去）
- UNKNOWN（无日期字段）继续不计入 worst；EXEMPT 与 UNKNOWN 语义独立
- JSON 输出加 `"exempt": [...]` 字段方便下游消费

`.github/workflows/check-csv-freshness.yml` 传白名单：

| 文件 | 真实发布节奏 |
|------|--------------|
| `provident_fund_rates.csv` | 年度（5 月初） |
| `education_overview.csv` | 年度（6 月底） |
| `gz_provident_annual.csv` | 年度（3 月底） |
| `sz_provident_annual.csv` | 年度（3 月底） |
| `zh_provident_dynamics.csv` | 月度（源站偶发不发） |
| `zh_bdc_registration.csv` | 季度（9 月才出 Q3） |
| `zh_price_filing.csv` | 源站 404 / 已下架 |
| `nbs_avg_wage.csv` | 年度（5 月发） |
| `stats_70.csv` | 月度（每月 18 日发布下月） |

## 效果

- 生效前 cron worst=2（黄/红邮件），生效后**worst 仍可能 =2 但只
  包含真正过期的源**（gd_construction / gd_services / gd_provident_annual /
  gz_housing_plan / sz_land_deals / sz_planned_supply 等），这些是真
  STALE 不豁免——保留邮件提醒，让用户/AI 可手动触发补齐
- 人眼扫 markdown 时 ⏸ EXEMPT 与 ❗ STALE 视觉区分明显
- 加白名单本身是零代码风险（纯 argparse 增参 + 字典查找）
