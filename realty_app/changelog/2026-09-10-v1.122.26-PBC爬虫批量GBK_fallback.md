# v1.122.26 — 5 个 PBC 爬虫 fetch_text 加 GBK 探测 fallback

**日期**：2026-09-10
**类型**：fix（真 bug，同 v1.122.25 GD 同因）
**影响**：央行 PBOC 5 个爬虫 → 解锁 10 行新数据（LPR +1 / OMO +3 / PBC fin_stats +1 / PBC region_sf +5）

## 问题根因

PBC 列表页 `http://www.pbc.gov.cn/zhengcehuobisi/...` 和
`http://www.pbc.gov.cn/diaochatongjisi/...` 同样存在
"Content-Type: text/html（不标 charset）但 body 实际 GBK" 现象。

5 个爬虫（crawl_lpr_history / crawl_mlf_history / crawl_omo_rr /
crawl_pbc_fin_stats / crawl_pbc_region_sf）的 `fetch_text` 都是：

```python
raw = urlopen(...).read()
for enc in ("utf-8", "gbk"):
    try: return raw.decode(enc)
    except: continue
return raw.decode("utf-8", "replace")
```

GBK 字节按 utf-8 解码"看似成功"（GBK 单字节 ASCII 段兼容 utf-8，
中文段变乱码但不抛异常），导致后续正则（"贷款市场报价利率"、
"中期借贷便利"、"公开市场业务交易公告"、"金融统计数据报告"、
"地区社会融资规模增量统计表"）全部 0 命中 → notices=0 / 拉不到新数据。

`check_csv_freshness` 看到 CSV 还"新鲜"（数据没动），所以 cron weekly
不会报警——**静默抓不到新数据**。

## 修法

跟 v1.122.25 GD 6 个爬虫完全同型：顶部加 `sys.path.insert` + 引用
`_gbk_probe.fetch_text_gbk`（共用 helper，gbk / gb18030 probe + utf-8
fallback + `errors='replace'` 容错）。

```python
ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(Path(__file__).resolve().parent))
from _gbk_probe import fetch_text_gbk  # noqa: E402

def fetch_text(url: str) -> str:
    return fetch_text_gbk(url, ua=UA, ctx=CTX)
```
