# v1.122.27 — 抽 crawl_common 共用 helper，11 个爬虫样板收齐

**日期**：2026-09-10
**类型**：refactor（无新功能、无 bug 修复，纯样板抽取）
**影响**：11 个 crawl_*.py 顶部 4 行样板 → 1 行 import

## 背景

v1.122.25 (GD 6 个爬虫) + v1.122.26 (PBC 5 个爬虫) 共改了 11 个
`crawl_*.py` 文件，每个都加同款 4 行样板：

```python
sys.path.insert(0, str(Path(__file__).resolve().parent))
from _gbk_probe import fetch_text_gbk  # noqa: E402

UA = {"User-Agent": "Mozilla/5.0 (compatible; realty-crawler/1.0)"}
CTX = ssl.create_default_context()


def fetch_text(url: str) -> str:
    """v1.122.26 起改用 _gbk_probe.fetch_text_gbk（共用 helper）。..."""
    return fetch_text_gbk(url, ua=UA, ctx=CTX)
```

11 个文件完全同型（除了 import 顺序 / docstring 内容略有差异）——
典型的"应该抽但被两次 fix 错过"的代码气味。

## 修法

新增 `realty_app/scripts/crawl_common.py`（v1.122.27 起）：

```python
from crawl_common import DEFAULT_UA, default_ctx, fetch_text, fetch_text_gbk
# fetch_text = fetch_text_gbk（同一函数对象）
```

11 个爬虫顶部样板收成 1 行：

```python
sys.path.insert(0, str(Path(__file__).resolve().parent))
from crawl_common import fetch_text  # noqa: E402
```

`fetch_text` 调用方零改动（函数名/签名一致）。

`crawl_pbc_region_sf.py` 因为还保留 `fetch_bytes` 用 UA/CTX，单独处理：
顶部 import `from crawl_common import fetch_text as _common_fetch_text`，
def fetch_text 改为 `return _common_fetch_text(url)`。

`crawl_gd_construction.py` / `crawl_gd_economy.py` 有特殊逻辑（inline GBK probe / 自定义 https 双栈），**不参与本次重构**，按既有逻辑跑。
