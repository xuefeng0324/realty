# v1.122.28 — stats_70.csv 补 2026/7 数据 + append_recent_stats70.py dedup bug 修复

**日期**：2026-09-10
**类型**：fix（真 bug）+ data
**影响**：stats_70.csv STALE 101d → 71d；解锁 140 行新数据（2026/7 完整月份 70 同比 + 70 环比）

## 问题根因

`append_recent_stats70.py`（v1.122.8 一次性脚本，注释里说"长期应该让 cmd_download 改成增量 replace"）有一个 dedup bug：

```python
by_month: dict[tuple[int, int], dict[str, dict[str, str]]] = defaultdict(dict)
for r in new_rows:
    ...
    by_month.setdefault(mk, {}).setdefault(r["city"], {})[r["date"]] = r
```

`by_month[mk][city]` 内层 dict 用 `date_str` 做 key，但 hugohe3 CSV 的 70 城市循环里，每个城市有"定基比 / 同比 / 环比"3 行（date_str 相同），最后写的环比覆盖前面所有。

具体表现：dry-run 报"[skip] 2026/7 不完整：同比 0/环比 70"——完整性闸门要求 70+70，所以拒绝追加。**脚本一直"看起来在跑"但实际从来没补成功过**。

## 修法

v1.122.28 把内层 dict key 改成 `(date, fixed_base)` 复合：

```python
by_month: dict[tuple[int, int], dict[str, dict[tuple[str, str], dict]]] = defaultdict(dict)
for r in new_rows:
    ...
    inner_key = (r["date"], r["fixed_base"])
    bucket = by_month.setdefault(mk, {}).setdefault(r["city"], {})
    if inner_key in bucket:
        continue
    bucket[inner_key] = r
```

修后 dry-run 输出 `[plan] 将追加 140 行`，完整性闸门通过。

脚本已支持 `--src` 参数（v1.122.8 就有），不需要改脚本。本机手跑成功补 140 行。
