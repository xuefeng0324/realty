## 修了什么

### `scripts/check_csv_freshness.py` EXEMPT 白名单从来没匹配上（v1.122.16 引入的 bug）

- **症状**: `check-csv-freshness.yml` cron 每天 02:30 UTC 跑，把10 个 EXEMPT 源都报为 STALE → GitHub Actions 邮件告警持续几周
- **根因**: v1.122.16 加 `--exempt-from-stale` 时构造 `exempt_set` 没带 `.csv` 后缀，但代码用 `csv_path.name`（带 `.csv` 后缀）做 `in` 比较，**永远 mismatch**

  ```python
  # v1.122.16 错的写法：
  exempt_set = {name.strip() for name in args.exempt_from_stale.split(",") if name.strip()}
  # exempt_set = {"gz_provident_annual", ...}            ← 不带 .csv

  for csv_path in iter_csvs(args.static_dir):
      is_exempt = csv_path.name in exempt_set
      # csv_path.name = "gz_provident_annual.csv"          ← 带 .csv
      # → False                                            ← 永远 False
  ```

- **修法**: 构造 `exempt_set` 时如果用户传的 name 没 `.csv` 后缀就自动补全。这样 CLI / CI workflow / 文档示例统一写 `gz_provident_annual.csv` 即可。

  ```python
  exempt_set: set[str] = set()
  for name in args.exempt_from_stale.split(","):
      n = name.strip()
      if not n: continue
      if not n.endswith(".csv"):
          n = n + ".csv"
      exempt_set.add(n)
  ```

- **兼容性**: 接受 `foo.csv` / `foo` / `.csv` 三种写法，老脚本调用不破
