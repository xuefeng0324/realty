# 2026-11-02 — 修底部 TabBar 图标全丢 + 70 城榜单点击无反馈（v1.122.55）

## 现象

1. 真机 / H5 底部导航只有文字（首页 / 找房 / 地图 / 行情 / 我的），
   图标位置是破图占位。用 `build:h5` 产物跑 22 页 e2e，每页稳定报
   `GET /static/tabbar/*.png 404`（首页 5 个、其余 tab 页各 2 个）。
2. 同时核对了 APK 包内 `unpackage/resources/__UNI__1BB4DA3/www/`：
   **根本没有 `static/` 目录**，说明整包里也没有这 20 个图标文件。
3. 全国 70 城榜单最长 70 行，点任意城市后，详情卡被插在列表**末尾**，
   用户点完当下屏幕毫无变化，看起来像「点了没反应」。

## 根因

- uni-app CLI（`npm run build:h5` / App 打包）**只把 `src/static/` 拷进产物**；
  仓库根的 `static/` 不会被拷贝。而 `src/pages.json` 的 `iconPath` 是相对
  `src/` 解析的，所以 `static/tabbar/home.png` 编译后指向产物根
  `/static/tabbar/home.png`，文件却从未被拷贝过去 → 404。
- 单测 `tests/navigation.test.ts` 原来按**仓库根** `resolve(root, iconPath)`
  检查图标文件是否存在，仓库根确实有文件，于是测试一直绿，掩盖了构建期丢失。
- 根 `static/` 里的 CSV 之所以没暴露问题，是因为它们全部通过
  `../static/*.csv?raw` 在编译期内联；`app-icons/`、`splash/` 只被
  HBuilderX 原生打包使用，路径与 web 产物无关。

## 改动

- `static/tabbar/`（20 个 png/svg）→ `src/static/tabbar/`（`git mv`，保留历史）。
  `pages.json` 与 `navigation.ts` 的相对路径不需要改。
- `tests/navigation.test.ts`：图标存在性断言改为 `resolve(root, "src", iconPath)`，
  与实际打包口径一致，并加注释说明「根 static 不会被拷贝」。
- `src/pages/stats70/stats70.vue`：详情卡加 `id="city-detail"`；
  `onPickCity()` 在 `nextTick` 后 `uni.pageScrollTo({ selector: "#city-detail" })`，
  点榜单立刻滚到刚生成的详情卡。
- 版本：`1.122.54 (333)` → `1.122.55 (334)`（patch，用户可见修复）。

## 验证

- `npm run type-check` ✅
- `npm test` ✅ 154 files / 1447 tests
- `npm run build:h5` ✅，产物出现 `dist/build/h5/static/tabbar/home.png`
- e2e core 套件：修前 **5/13** → 修后 **13/13**；22 页 `console errors: 0`
- `layout-diff` ✅ PASS（签名 686，−4 占 0.58%；锚点组 49/49 一致）
- Playwright 实测点「大连」：`scrollY 0 → 3941`，`#city-detail` 顶部 251px 且在视口内

## 取舍

- 已安装的旧 APK 仍是破图标，**必须重新打整包 / 发 OTA** 才会带上图标；
  本次只保证源码与构建产物正确。
- 其余根 `static/`（CSV、app-icons、splash、update）保持原位不动：
  CSV 走 `?raw` 内联、原生资源由 HBuilderX 读取，整体搬迁风险大于收益。
- 点击自动滚动依赖 `uni.pageScrollTo({ selector })`（App 2.0+ / H5 支持）；
  小程序端会退化为不动，但不影响数据展示。
