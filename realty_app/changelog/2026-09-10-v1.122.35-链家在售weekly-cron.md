## 改了什么

`scripts/crawl_lianjia_listings.py`（v0.10.0 已存在，但**无 workflow**）现在挂上 GitHub Actions weekly cron，每周二 03:00 UTC 自动跑：

- **城市**：深圳（sz）/ 广州（gz）/ 珠海（zh）3 城
- **来源**：`<city>.lianjia.com/ershoufang/pg{n}/` HTML 公开列表页（已实测 2026-07-12 还能稳定拿到数据）
- **节奏**：每城 10 页 × ~30 条 = ~300 条；3 城合计 ~900 条/周
- **模式**：`--append`（按 source_listing_id 去重保留旧行）— v0.10.0 脚本本身已支持
- **不动**：`--update-communities`（避免空 district 污染 `compute_school_premium.py` 的 district compare 测试）

## 已知 trade-off

| 维度 | 内容 |
|------|------|
| ✅ 优点 | 链家在售二手从「60 套深圳手抓样本」逐步扩到「3 城每周 ~900 条自动增量」 |
| ✅ 优点 | `--append` 模式保留所有 DERIVED（含 v1.122.34 宝安 40 套）与原 60 套 REAL，不会覆盖式清空 |
| ⚠️ 缺点 | 新抓到的小区大多 `community_id=0`（seed 里没有的），findhouse 页面会过滤；真正可见增量 < 抓取量 |
| ⚠️ 缺点 | 链家 anti-bot 不保证 100% 成功率（脚本注释"70+ 城市不限速"，但 WAF 不定期变化）；首次失败可在 Actions 页面手动重试 |
| ⚠️ 缺点 | GitHub Actions 默认 IP 段链家可能在某些时段拉黑；如连续 2 周失败考虑加代理或换源 |
| 🔄 替代方案 | 把 lianjia 加进 `crawl-weekly.yml` 跟 anjuke 同跑（与安居客共享 P0 阶段）— 拒绝：会污染现有每周流程；改一处流程影响大 |
| 🔄 替代方案 | 写到 `crawl_anjuke.py` 里走同一 cron — 拒绝：lianjia/anjuke 是不同源不同解析逻辑，硬塞一个文件不可维护 |
