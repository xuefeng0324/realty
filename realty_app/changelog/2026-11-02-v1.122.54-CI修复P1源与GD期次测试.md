# 2026-11-02 — 修 `crawl-weekly` 与 `realty_app tests` 两条流水线（v1.122.54 补丁，不发版）

## 现象

GitHub Actions 每天/每周邮件报红：

- `realty_app tests`（run 41404296230，2026-11-02）：单测 4 个失败 + 覆盖率报 `coverage` 目录不存在。
- `crawl-weekly`（run 41364677529，2026-11-01）：P1 门禁 exit 1，3 个来源失败。

## 根因（都拿 CI 日志逐条核对过，不是猜）

1. **4 个广东宏观单测硬编码期次**
   `tests/gdRetail / gdIndustrial / gdFaInvestment / gdRealEstateBrief` 把「最新期次」
   写死成 `2026_H1 / 2026_01_05..09`。10-26 每周爬虫把官方「前三季度 / 1-8月」
   发布写进 CSV 后，最新期次变成 `2026_Q3`，断言立刻红。这是 v1.122.54 记录过的
   同一类问题（NBS 累计口径），当时只修了 NBS 三个文件，漏了广东这四个。

2. **`crawl_sz_provident_annual.py` / `crawl_gz_provident_annual.py` 在 CI 上直接
   SyntaxError**
   ```
   "paid_units_wan": f"{one(r'实缴单位([\d.]+)万家'):g}",
   SyntaxError: f-string expression part cannot include a backslash
   ```
   PEP 701 到 **Python 3.12** 才允许 f-string 表达式里出现反斜杠；CI 用 3.11，
   本机是 3.12，于是「本地跑得好好的、CI 每次 exit 1」。把裸正则先算到变量再拼。

3. **`crawl_zh_price_filing.py` 列表页 404 未兜底**
   珠海住建局备案列表 `index.html` 已 404（`docs/FRESHNESS_CHECK.md` 早有记录），
   脚本在 `first = fetch(list_url(1))` 抛 traceback → exit 1 → P1 门禁红。
   改为：有 last-good 就保留并打印 `[warn]`、返回 0；无 last-good 才返回非 0。
   同时在分页中途失败时用已发现条目继续，不再整体崩。

## 改动

- 上述四个 `tests/gd*.test.ts`：最新期次只校验形状（`20xx_(H1|Q1-4|MM_DD)`）+ 合理区间，
  数值断言改为锁定**已发布的历史期次**（如 `2026_H1`、`2026_01_07`），官方再发新期不会再红。
- 两个公积金年报爬虫：预计算正则结果，兼容 Python 3.11。
- 珠海价格备案爬虫：列表不可达 / 分页失败 / 0 条目 三处都改为「保留 last-good + 告警」。
- `run_weekly_source_group.py`：来源失败时把**日志尾部 12 行**同步成 annotation。
  公开仓库无需登录即可在 Actions 页面看到失败原因（此前必须下载需要权限的 artifact）。
- `vitest.config.ts`：`exclude` 增加 `unpackage/**`、`dist/**`、`coverage/**`、`node_modules/**`。
  本机 HBuilderX 构建产物混进 v8 分母，本地覆盖 35.41% < 45% 必红，而 CI 没有这些目录 → 两边口径不一致。

## 取舍

- 珠海价格备案源站确实已死，`[warn]` 返回 0 会**掩盖停更**；补位手段是
  `check_csv_freshness` 的 STALE 检查（该源本来就在 EXEMPT 白名单里，说明邮件不会报）。
  真恢复后应把入口改到新 URL，而不是长期靠 last-good。
- 单测放宽了「最新期次」的数值断言，等于放弃对最新一期的数值校验；换来的是官方发布节奏
  不再直接打红 CI，历史期次数值仍被锁定。
- `unpackage/**` 排除只是对齐本地与 CI，不改 CI 门槛（45/45/40/40）。
