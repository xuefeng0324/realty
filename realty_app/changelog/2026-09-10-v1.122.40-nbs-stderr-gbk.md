## 背景

v1.122.37 修 shibor/omo_rr/mlf_history 时我用了 `sys.stdout = io.TextIOWrapper(...)`。
v1.122.38 修 8 个 safe_* 同 pattern。
v1.122.39 修 2 个 pbc_* 同 pattern。

**漏修的**：15 个 `crawl_nbs_*.py` 也踩同一个 GBK bug——NBS 公告页里有 `\ufffd`（乱码字符）让 Windows GBK stdout 编码失败。

**为什么 v1.122.37-39 没发现**：
- 当时 smoke test时这些脚本**没在测试集里**——我focus 在 PBOC+SAFE
- 直到 v1.122.40 freshness v5 扫描才暴露 `crawl_nbs_energy / crawl_nbs_retail` 等实际 GBK fail

## 改了什么

### 1. 给 15 个 `crawl_nbs_*.py` 加 sys.stdout UTF-8 包装

跟之前 patch 模式**改进版**：

```python
# 同时包 stdin/stdout/stderr——之前 patch 只包 stdout
# 但 NBS 脚本有 print(..., file=sys.stderr) 调用
# v1.122.37-39 漏 stderr 包装是局部失误
if sys.stdout.encoding and sys.stdout.encoding.lower().replace("-", "") != "utf8":
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding="utf-8", errors="replace")
    sys.stdin = io.TextIOWrapper(sys.stdin.buffer, encoding="utf-8", errors="replace")
```

**patch 文件**：
- `crawl_nbs_avg_wage.py`、`crawl_nbs_cpi.py`、`crawl_nbs_energy.py`
- `crawl_nbs_fa_investment.py`、`crawl_nbs_gdp.py`、`crawl_nbs_income.py`
- `crawl_nbs_industrial.py`、`crawl_nbs_industrial_profit.py`
- `crawl_nbs_pmi.py`、`crawl_nbs_ppi.py`、`crawl_nbs_real_estate.py`
- `crawl_nbs_retail.py`、`crawl_nbs_service_index.py`
- `crawl_nbs_trade.py`、`crawl_nbs_unemployment.py`

### 2. 兼容性确认

- **stdout + stderr + stdin 三件套** 同时包——下次新增爬虫使用 `print(..., file=sys.stderr)` 不会再踩坑
- v1.122.37-39 已 patch 的脚本（shibor/omo_rr/mlf_history/8 safe/pbc_fin/pbc_region）都用 `print()` 默认 stdout——没用到 stderr，**不需回补**
