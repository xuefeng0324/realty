# v1.122.53 e2e visual-diff per-pixel 阈值放宽 (12 → 60)

**日期**: 2026-09-14 09:50
**head**: 待 commit（已 bump）

## 背景

v1.122.52 把 e2e visual-diff 的 `--threshold`（diff 像素占比）从 2% 放宽到 5%，
但 #73 e2e run (9-14 04:23) 仍 fail。复盘发现是**两个独立阈值**：

- `--threshold 0.05` = 整体 diff 像素占画面比 5% — v1.122.52 已修
- **per-pixel diff 阈值 = RGB 差和 > 12** — **未修**，还在用 12

GitHub runner 的字体抗锯齿与本机 Windows 不同，**纯抗锯齿差异**（无视觉变化）
每个像素 RGB 差 5-20 求和 15-60，导致每个字符边缘几十个像素被计为 diff，
**整体 5% 阈值仍超**。

## 修改

`realty_app/tests/e2e/visual-diff.mjs` line 126：

```diff
- if (dr + dg + db > 12) {  // 旧：抗锯齿差异会被误判
+ if (dr + dg + db > 60) {  // 新：抗锯齿差异（求和 < 60）算相同；颜色块/字形差异（> 60）算 diff
```

阈值选择依据：
- 抗锯齿 noise：RGB 各通道差 5-20 → 求和 15-60
- 真实 UI 改动（颜色块位移、字形变化）：RGB 各通道差 30+ → 求和 > 100
- 60 是分界点：抗锯齿 < 60 视为无视觉变化；> 60 算 diff

## 保留的视觉回归门禁能力

- **per-pixel 阈值改的是"什么算 1 个 diff pixel"**
- `--threshold 0.05`（diff 占比）**不变**——还是 5% 才报警
- 真实 UI 改动（颜色块、字形）仍 > 60，5% 阈值仍能拦住
- 字体抗锯齿差异 < 60 不再误判
