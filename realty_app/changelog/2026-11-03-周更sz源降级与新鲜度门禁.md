# 周更 sz 源降级 P2 + 数据新鲜度门禁（2026-11-03，不发版）

仅 CI / 脚本 / 文档改动，按 VERSIONING.md 不 bump 版本。

## 背景

`crawl-weekly` 在 2026-11-02 的结构性修复（超时/重试/push 冲突）全部生效后仍然红，
剩余失败全部是「源站侧」问题而非代码 bug：

1. `sz-education` / `sz-planned-supply` / `sz-affordable-projects`：
   GitHub runner 到 `szeb.sz.gov.cn` / `zjj.sz.gov.cn` 系统性 `Connection reset`，
   两轮重试均不通；本机（国内网络）直连正常。留在 P1 硬门禁只会周周红，
   把真正的新问题淹没。
2. `zh-price-filing`：珠海「商品房价格备案公示」栏目 2026-07 起 404。
   2026-11-03 复测：目录 URL 403、`index.html` 404，官网导航仍挂链接但
   目标页不存在（本地与 CI 现象一致），不是网络问题，是栏目被撤。

## 改动

1. **sz 三源 P1 → P2**（`run_weekly_source_group.py`）：失败只告警不阻塞；
   P1 从 23 源变 19 源，P2 从 15 源变 18 源，P2 step 上限 18 → 25 分钟。
2. **`zh-price-filing` 停更**：从源清单移除并注释原因；`zh_price_filing.csv`
   保留 last-good（该文件本就在 check-csv-freshness 的 EXEMPT 白名单里）。
3. **新增数据新鲜度门禁**（防「降级后静默停更」）：
   - `run_weekly_source_group.py` 新增 `--health-file`：每组跑完把**成功**来源的
     `last_success` 写入 `static/source_health.json`；全组失败不写文件，
     避免产生没有信息量的空提交。
   - 新增 `scripts/check_source_freshness.py`：watch list 里的来源超过
     `--max-age-days`（线上 21 天）无一次成功 → `::error` + exit 1。
     门禁按「上次成功抓取」判定，**不用** CSV 的 `publish_date`——教育统计
     按年发布、供应计划按季度发布，publish_date 老旧是常态而非故障。
   - workflow 新增 `freshness_gate` step（supplementary_commit 之后、
     最终门禁之前），盯防三个降级 sz 源；最终质量门禁把 `freshness` 纳入硬门禁。
   - `static/source_health.json` 种子时间取自各 CSV 最后一次数据提交时间
     （git log）：sz-education 2026-11-02、sz-affordable-projects 2026-11-02、
     sz-planned-supply 2026-10-26。即 21 天窗口内通路恢复就自动转绿；
     恢复不了，11 月中下旬门禁会准时打红提醒换通路。
4. **契约测试**：P1/P2 清单按新分组更新；新增 4 个用例——健康档案只记成功、
   全组失败不写档案、freshness 脚本对新鲜/过期/无记录/坏档案的判定、
   仓库种子档案结构检查（不随时间腐坏的断言写法）。

  兜底是 21 天新鲜度门禁；想彻底恢复需要国内网络通路的 runner（见下一步建议）。
