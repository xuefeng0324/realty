## 1. 修复地图崩溃（用户实机截图反馈）

**症状**：v1.120.0 APK 安装后打开"地图找房"，控制台报
```
TypeError: fetch is not a function
    at loadCommunityMarkers (map-view.vue:1001)
```
地图完全空白，底部弹出"加载失败"。

**根因**：`src/pages/map-view/map-view.vue` 的 `loadCommunityMarkers()`
为了拿小区经纬度，写了：
```ts
const csvText = await fetch("/static/seed/communities_geo.csv").then((r) => r.ok ? r.text() : "");
```
H5 端 `fetch` 是浏览器 API；**App-Plus WebView 容器没有全局 `fetch`**（uni-app 在
App 端只暴露 `uni.request`/`plus.net`）。这条路径在 v0.92.0 之后就开始靠
`fetch` 跑数据，但因为 wgt OTA 一直没人装到真机验证，漏洞未暴露。

**修复**（`src/pages/map-view/map-view.vue`）：
- 移除 `fetch` + 本地 CSV 解析路径
- 改走 `store.getCommunityGeoByCity(cityId)`（importer 已经在 `seedSnapshot.ts`
  里把 `communities_geo.csv` 内联进 wgt 内存，`DataSnapshot.communityGeo` 早就有）
- 删除死代码 `parseGeoCsv()`，新增一行占位 `_parseGeoCsvRemoved_v1_121_0()`
  注释（避免再有同款死代码）

未引入新依赖；不增加 wgt 体积。

## 2. CI 自动 APK 可选 job

**改动**：`.github/workflows/build-app-wgt.yml` 在 `build-wgt` 之后新增 `build-apk` job。

**设计**：
- 默认行为不变（没 secret 时整个 job `if: steps.creds.outputs.skipped != 'true'` 跳过，CI 仍然绿）
- 配 `DCLOUD_USERNAME` / `DCLOUD_PASSWORD` GitHub Secrets 后，自动调 `@dcloudio/uni-cli-plugin-package`
  出 APK，artifact 名 `realty_app-apk-<versionCode>`，retention 30 天
- 失败不阻塞 OTA（`exit 0` 兜底），本地 HBuilderX 完整打包仍可补位

**注意**：DCloud 没有稳定公开的云打包 npm CLI，本 job 是"基础设施就绪 + 失败兜底"，
用户后续若要让 APK 走 CI 出，可选：
- A. 把官方 CLI 包名填对（实测后改 path）
- B. 走 `apk-cloud-build.yml.example`（暂未提供；走方案 A 见 `docs/BUILD_APK.md`）
- C. 直接本地 HBuilderX（当前最稳）

## 3. 应用图标重做（用户反馈"自动生成的应用图标有点丑"）

**生成器**：`realty_app/scripts/build_app_icons.mjs`（Node 22+ 零依赖）
- 1024×1024 主稿 `realty_app/static/app-icon.svg`：深蓝渐变背景 + 4 根 amber 柱 + 第 3 柱顶 amber pin 圆点
- 直接输出 `static/app-icons/{72,96,144,192}.png`（不进仓库被 ignore 的 unpackage；HBuilderX 打包时手工拷到 `unpackage/res/icons/`）
- 不依赖 cairosvg / Pillow（环境装不上时仍可用）

**已知问题 / 后续**：
- 当前图标只覆盖了 app-plus `icons/` 安卓通用尺寸；iOS / 启动屏 splash 用 manifest 内置图标（HBuilderX 默认）暂未替换
- 文档同步：`docs/BUILD_APK.md` 新增「应用图标」段；`docs/icon-192-preview.png` 留档当前效果
