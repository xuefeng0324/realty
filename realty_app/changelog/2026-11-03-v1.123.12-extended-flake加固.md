# v1.123.12 extended e2e flake 加固（metro_benefit / listing_minidim 条件等待）

## 背景

extended 套件中 `smoke_metro_benefit.mjs` 与 `smoke_listing_minidim.mjs` 偶发 flake（重跑即绿）。根因是两类经典不稳定等待：

1. **`waitUntil: "networkidle"`**：uni-app H5 的挂起请求 / 慢资源会让 networkidle 超时；反过来 networkidle 也只覆盖网络层，不保证应用渲染完成。
2. **固定 `waitForTimeout` 盲等**：负载高时不够长（读数偏低/点不到元素），空闲时浪费数秒。

## 修改（仅 e2e，两文件）

### `tests/e2e/smoke_metro_benefit.mjs`
- `page.goto` / 两处 `page.reload`：`networkidle` → `domcontentloaded`（reload 显式 30s 超时）。后续 `[data-home-city]` / CARD / 卡片标题的显式 waitFor 已完整覆盖应用就绪面。
- `pickCity` 末尾固定 1200ms → `waitForFunction` 等壳层 `[data-home-city]` 文案真正包含目标城市（15s 超时）。

### `tests/e2e/smoke_listing_minidim.mjs`
- **默认端口 5175 → 5174**：对齐 `npx serve -l 5174`；suite 内由 `REALTY_E2E_BASE_URL` 覆盖不受影响，单跑默认值原来指向死端口属潜在跑不通隐患。
- `page.goto`：`networkidle, 15s` → `domcontentloaded, 20s` + `.picker-value` 可见等待。
- `pickCity`：sheet-item 点击前先等其可见；点击后盲等 3500ms → `waitForFunction` 等 `.picker-value` 文案切城（15s）+ `.listing-row` 首行可见（15s）+ 500ms settle（覆盖 picker 文案先于列表重渲染的窗口，防读到上一城残留行）。
- 「应用」筛选后盲等 3500ms → 等 `.minidim-row` 首条可见（15s）。
- 行数读取前加 `waitForFunction(.listing-row 数 >= 3)`（15s）：防首屏渲染慢导致 count 偏低的假失败；真实 <3 仍超时失败，门禁语义不变。

## 不改的部分

- 应用代码 / DOM / 样式 / 路由零变更，layout 基线不动。
- 断言项（行数、徽章、颜色分档、标签数等）全部保留原阈值。
- 其余 7 条 extended 用例与 core 13 条未动（同 pattern 的 `smoke_metro_walk` 历史稳定，本轮不扩面；如后续也 flake 再按同法加固）。
