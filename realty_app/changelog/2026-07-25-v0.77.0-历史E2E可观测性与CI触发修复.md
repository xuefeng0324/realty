# v0.77.0 历史 E2E 可观测性与 CI 触发修复

## 背景

历史全量 E2E 已能对少量浏览器瞬时网络错误重试一次，但此前只有终端文本汇总，CI 长期运行后不便统计重试频率；同时 E2E 工作流监听自身变更的路径与实际文件名不一致。

## 改动

- 历史运行器每次结束都生成 `tests/e2e/artifacts/history-summary.json`。
- 报告记录运行时间、基础地址、并发数、超时、通过/失败数量、失败详情和每次瞬时错误重试结果。
- 定时与手动 CI 在任务摘要中展示通过率、耗时、重试次数和各重试脚本最终状态。
- 修复 `.github/workflows/realty-app-e2e.yml` 的 pull request 路径过滤规则。
- 保持重试白名单和最多一次重试不变，真实业务断言失败不重试。

## 验证

- `npm run type-check`
- `npm test`
- `npm run build:h5`
- `npm run test:e2e:history`
- 检查生成的 `history-summary.json` 字段与实际运行结果一致。

## 后续可做

- 累积多次 CI 报告后，如瞬时错误持续集中在高并发阶段，再依据数据自动降低历史套件并发数。
- 真机验证 Android、iOS 和微信小程序的安全区域、横屏、原生地图及系统字体缩放。
