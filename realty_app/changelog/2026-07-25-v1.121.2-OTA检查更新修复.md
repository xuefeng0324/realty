# v1.121.2 — OTA 检查更新无反应修复

日期: 2026-07-25
类型: Bug fix
影响: 所有 v1.120.0+ 装包用户（地图 OTA 一直更新不到）

## 1. 症状

用户反馈："点击检查更新根本没反应"。

## 2. 根因（两段）

### 2.1 CDN 列表顺序反了

`remoteFetch.getStaticBases()` 之前是：
```ts
[
  gcore.jsdelivr.net,
  fastly.jsdelivr.net,
  cdn.jsdelivr.net,   // 大陆经常被墙/限速
  jsdelivr.b-cdn.net,
  raw.githubusercontent.com
]
```
jsDelivr 多个镜像在大陆网络下大概率超时（每个 15s），5 个全跑 75 秒——用户感觉"没反应"。

### 2.2 raw 上没有 wgt 二进制

v1.120.0 的修复把 raw 加进 fallback 列表，**但忘了 raw 不支持二进制下载**：
- raw.githubusercontent.com 对 `.wgt` 这种二进制文件会返回 HTML 包装（404 页面）
- 即使清单能拉到，wgt 也会下载失败

`appUpdate.ts` 的 `fetchManifestWithBase()` 把 wgt URL 改写到"命中的镜像根"，如果命中的恰好是 raw，wgt 就死。

## 3. 修复

### 3.1 优先级调正

`src/local/remoteFetch.ts`：
- 把 `raw.githubusercontent.com` 提到第一位（大陆直连最稳，最快）
- jsDelivr 系列保留作 fallback

### 3.2 manifestBase ≠ wgtBase

`src/utils/appUpdate.ts`：
- 新增 `selectWgtBase(manifestBase, candidates)` 工具：
  - manifest 命中 raw → wgt 强制走 jsDelivr 系列
  - manifest 命中 jsDelivr → wgt 走同一镜像
- `fetchManifestWithBase()` 返回 `{ manifest, manifestBase, wgtBase }`
- `checkAppUpdate()` 用 `wgtBase`（不是 manifestBase）做 wgt URL 改写

### 3.3 测试

`tests/appUpdate.test.ts`：
- 3 个新增用例覆盖 selectWgtBase（jsDelivr 命中、raw 命中、所有 base 都是 raw）

## 4. 验证

- `npm run type-check`: ✅ 通过
- `npm test`: ✅ 752/752 通过
- 实机：装 v1.121.2 后应能在 1-2 秒内看到"有新版本 v1.121.2"提示

## 5. 后续

- jsDelivr 在大陆仍然不稳，未来可考虑把 `static/` 全部迁到国内 CDN（如阿里云 OSS / 七牛）。
  需要在 `getStaticBases()` 加一个 `realty:cdnBase` 覆盖位（已支持），下次直接填阿里云地址即可。
- `appUpdate.ts` 错误信息可以更友好：现在返回"无法访问更新服务器：所有 CDN 镜像均失败"，可以改成把命中的镜像、错误码也带回来。
