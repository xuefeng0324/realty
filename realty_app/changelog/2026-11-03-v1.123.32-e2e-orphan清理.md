# v1.123.32 E2E orphan 清理 + `_all_smoke` 修复

## 背景

v1.123.31 报告里留了一个观察项：`tests/e2e/` 下仍有 12 个脚本不在任何 suite（core / extended / v093_097），既没有 CI 消费，也没有文档把它们当命令。它们源于 v0.26～v0.46 的 trend/map 系列卡片；这些卡片在 v1.121.x 迁往 data-tools 或直接退役后，脚本就成了「写着断言、永远没人跑、一跑就红」的负资产。

本轮先全部实跑取证，再决定处置，而不是凭文件名猜。

## 改动

**A. 12 个 stale orphan 全部实跑 → 全红 → 删除**

`smoke_bedroom_area` / `smoke_decorate_age` / `smoke_district_meta` / `smoke_feature_premium` / `smoke_listing_freshness` / `smoke_map` / `smoke_orientation_floor` / `smoke_scatter` / `smoke_tag_combination` / `smoke_life_convenience` / `smoke_district_compare` / `smoke_trend11`

实跑结果：12/12 失败，失败原因统一是「卡 not visible / 行不存在 / 城市切换不生效」——断言对象已迁走或退役，脚本本身无修复价值；均已确认不在 `run_suite.mjs`、`package.json`、CI workflow 与当前验收文档的命令列表里（README 中仅历史版本段落提及，属归档叙述，不改写）。

**B. `_all_smoke.mjs` 修复（真跑时暴露的两个 bug）**

1. **成员来源**：原本 `readdirSync` 全量跑，必然把上面 12 个 stale 脚本计入失败。改为解析 `run_suite.mjs` 的 26 个成员，与单一事实来源同步。
2. **判定逻辑**：原 `exitOk && (looksLikePass || /PASS/)` 把大量 `exit 0` 的脚本误判为 FAIL（首跑 11 pass / 15 fail，其中 14 个 `exit 0`）。改为以退出码为准；同时补上与 `run_suite` 相同的 6 个环境变量（`E2E_BASE_URL` / `E2E_URL` / `REALTY_E2E_BASE_URL` / `REALTY_E2E_URL` / `BASE_URL` / `SMOKE_BASE`），消除 env 缺省值差异导致的 `smoke_dashboard_feature_matrix` 假失败。

修复后 `node tests/e2e/_all_smoke.mjs` = **26 pass / 0 fail**。

**C. 防回归门禁（`tests/buildIntegrity.test.ts`）**

- 12 个已退役脚本路径必须不存在（防止「复制旧脚本改个名」复活死断言）
- `_all_smoke.mjs` 必须引用 `run_suite.mjs` 且不得再用 `readdirSync`
