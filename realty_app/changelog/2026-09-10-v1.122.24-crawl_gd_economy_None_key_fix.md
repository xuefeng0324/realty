# v1.122.24 (2026-09-10) — crawl_gd_economy.py 防 None key 报错

**versionCode**: 302 → 303
**性质**: 真 bug 修复（cron weekly 会爆）

---

## 修了什么

### 症状

跑 `crawl_gd_economy.py` 报：

```text
ValueError: dict contains fields not in fieldnames: None
  File "E:\...\scripts\crawl_gd_economy.py", line 363, in atomic_write
    w.writerows(rows)
```

### 根因

本机探测发现：

```text
gd_economy.csv header: 32 fields
gd_economy.csv row 4 (2026_01_07): 33 fields  ← 比 header 多 1 个
```

CSV 第 5 行（`2026_01_07` 那行）因**多了一个逗号**导致 DictReader 多读一列；那列没有 header → DictReader 返回 **None 作为 key** → DictWriter 写时 `key=None` 不在 fieldnames 里 → ValueError。

**为什么之前没爆**：之前 `parse_brief` 解码乱码 → 找不到 GDP → `return None` → 没 row 进 merged → atomic_write 拿到空 row 或只 1-2 条，不爆。v1.122.23 GBK fix 让 decode 真生效后 → parse_brief 找到 GDP → row 进 merged → atomic_write 写入第 5 行（带 None key）→ 爆。

简单说：**GBK fix 让本就有病的 CSV 显式触发 bug**——这是 v1.122.23 上线后**首次 cron weekly**就会爆的潜在故障。

### 修法

`atomic_write` 加防御性过滤；`load_existing` 也加同样的防护：

```python
# load_existing: 防御 None key（旧 CSV 行可能多逗号产生 None key 列）
safe = {k: v for k, v in r.items() if k is not None and k in FIELDS}

# atomic_write: 防御性过滤（兜底，覆盖任何来源的 row）
safe_rows = []
for r in rows:
    safe = {k: v for k, v in r.items() if k is not None and k in FIELDS}
    for k in FIELDS:
        safe.setdefault(k, "")
    safe_rows.append(safe)
```

同时**清理旧 CSV 残余 None key 列** —— atomic_write 会重写 CSV，下次写出去就是干净格式（32 fields）。
