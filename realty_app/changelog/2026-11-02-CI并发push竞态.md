# 2026-11-02 — 修自动提交工作流的并发 push 竞态（不发版）

## 现象

手动 dispatch `crawl-weekly` 后，`P0 · 提交挂牌核心快照` 步骤失败，整条流水线红。
同一天还有 `realty_app tests` 因为期次断言红、`crawl-weekly` 因 P1 源语法错/404 红。

## 根因

抓取类 workflow 用 `actions/checkout` 在 run 开始时检出 main，跑完 P0（约 10 分钟）
后直接 `git push`。这 10 分钟里其它 workflow 完全可能推进 main：

- `build-app-wgt.yml` 会提交 `static/update/`（OTA 清单）；
- `crawl-daily-wangqian.yml` 日更；
- `crawl-lianjia-weekly.yml` 周更；
- 人工 push（本次就是我在 crawl 运行期间推了 `f8ba13f`）。

于是 P0 的 push 变成非快进，整条流水线红。这不是某一次偶发，而是**只要两个
自动提交 job 时间重叠就会复现**的系统性缺陷，也是 crawl-weekly 长期红的主因之一。

## 改动

- 新增 `realty_app/scripts/git_push_retry.sh`：`git pull --rebase --autostash` 后再 push，
  失败重试 4 次（8/16/24/32 秒退避），rebase 冲突则 `git rebase --abort` 后重试，
  最终仍失败才 exit 1。
- 5 条会自动提交的 workflow 全部改用它：
  - `crawl-weekly.yml`（P0 提交 + P1/P2 汇总提交，2 处）
  - `crawl-monthly-stats70.yml`
  - `crawl-lianjia-weekly.yml`
  - `crawl-daily-wangqian.yml`
  - `build-app-wgt.yml`（保留原失败诊断块与显式 token URL）

## 验证

- `bash -n scripts/git_push_retry.sh` ✅
- 沙箱真复现：bare 远端 + A/B 两个克隆，A 先 push，B 基于旧 SHA 提交后执行脚本
  → 自动 rebase 成功并 push，远端最终同时有 `a.txt` 和 `b.txt`（两个提交都在）
- 无 UI 改动，`npm test` 1447 用例仍全绿（本次仅改 workflow/脚本）

## 取舍

- rebase 冲突（两个 bot 改了同一个 CSV 的同一行）仍会失败，这是应有的行为：
  冲突说明数据口径真的打架，需要人看一眼，不能用 `-X theirs` 掩盖。
- 只解决 push 竞态，不改变各 workflow 的抓取顺序与门禁语义。
- 本次改动属于 CI/脚本，按 `docs/VERSIONING.md` 不 bump 版本。
