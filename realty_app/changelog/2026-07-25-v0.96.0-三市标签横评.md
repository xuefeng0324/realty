# v0.96.0 — 三市标签横评（listing-filter mini 卡 + 全链路接入）

日期：2026-07-25

## 目标

`static/seed/listing_tags_summary.csv` 一直在仓库里 52 行 8 KB，**但从未被 `snapshotLoader.ts` 加载**，因此 `snapshot.listingTagSummaries` 一直是空数组。v0.96.0 第一次把这条数据正式接入派生链路：

- 接入 `LocalListingTagSummary` 类型 → `DataSnapshot.listingTagSummaries` 字段
- 接入 `parseListingTagsSummary` parser → `snapshotLoader.ts` 的 OPTIONAL 列表
- 接入 `seedSnapshot.ts` 的 `import` + `inputs` 字面量
- 新增 store 接口 `getListingTagSummaries()` / `getListingTagSummariesByCity()`
- 派生 `listingTagsComparison.ts`（3 个公开函数）
- listing-filter 页加「🏷️ 三市标签横评」卡

## 数据源

| 字段 | 用途 |
|------|------|
| `static/seed/listing_tags_summary.csv` | 52 行 × (city_id, city_name, tag, count, share) |
| `local/types.ts` 新增 `LocalListingTagSummary` | 类型定形 |
| `local/importer.ts` 新增 `parseListingTagsSummary` | CSV parser |
| `local/snapshotLoader.ts` 加入 OPTIONAL | 自动加载 |
| `local/seedSnapshot.ts` 加入 import + inputs | 本地 dev 模式可立刻用 |
| `local/store.ts` 新增 2 个 store 函数 | 全表 + 按城市 |

## 关键改动

### 1. 数据链路 4 个文件（types / importer / snapshotLoader / store / seedSnapshot）

- `types.ts`: 新增 `LocalListingTagSummary`；`DataSnapshot` 加 `listingTagSummaries: LocalListingTagSummary[]` 字段
- `importer.ts`: 加 import + `parseListingTagsSummary(csvText)` parser + 输出字段
- `snapshotLoader.ts`: OPTIONAL 列表加 `["listingTagsSummaryCSV", "listing_tags_summary.csv"]`
- `store.ts`: import `LocalListingTagSummary` + `getListingTagSummaries()` / `getListingTagSummariesByCity()`
- `seedSnapshot.ts`: 本地 dev 模式 import `?raw` + `inputs.listingTagsSummaryCSV = ...`

### 2. `src/local/listingTagsComparison.ts`（新增）

三个公开函数：

- `summarizeListingTagsByCity(topN=8)` → `CityTagSummary[]`
  - 按 cityId 聚合，每市输出：城市名 + 总 tag 数 + 总 count + topN 标签
  - 默认按 cityId 升序

- `getTagPenetrationCompare()` → `TagPenetration[]`
  - 按 tag 全样本聚合，返回 { tag, byCity: {cityId→share, count}, presentIn, avgShare }
  - 排序：presentIn 多 → avgShare 大

- `getCityTagSignature(cityId, boost=1.5)` → `TagSignatureEntry[]`
  - 找"该市 share ≥ 其他市平均 × boost"的标签，回答"城市标签特色"
  - 排序：share 降序

### 3. listing-filter 接入

`src/pages/listing-filter/listing-filter.vue`：

- 新 import + 类型
- 5 个 computed：`tagCitySummary` / `tagPenetrationCompare` / `tagPenetrationTotalRows` / `cityTagSignature` / `tagCityName`
- 1 个 helper：`tagPenetrationCompareRow(row)` 将 `byCity` 字典转有序数组
- 新卡「🏷️ 三市标签横评」插在 v0.95.0 卡后：
  - 顶部：标签总数 + 有标签数据城市数
  - 主体：Top 6 标签的多城分布（每行：tag 名 + 多行 progress bar + 城市 share 文本）
  - 副卡：当前城市 标签特色 Top 4（含 "vs 其他市平均" 对比）
  - 脚注：自解释 (52 行预聚合)
  - 过滤：仅显示 presentIn ≥ 2 且 avgShare ≥ 0.01 的标签，去除噪点

CSS：新增 `.tag-penetration-row` / `.tag-penetration-head` / `.tag-name` / `.tag-penetration-bar` / `.tag-penetration-cell` / `.tag-penetration-fill` / `.tag-penetration-label` 一组样式，沿用现有 `drift-row` / `drift-up` 排版。

## 设计取舍

| 维度 | 决策 | 理由 |
|------|------|------|
| 进 listing-filter 而非 dashboard | dashboard 已饱和 | listing-filter 是用户挑房页面，"市场视角"上下文最贴近 |
| 提前过滤 presentIn ≥ 2 + avgShare ≥ 0.01 | 避免刷两条孤立数据 | 单市独有标签不具横向可比，列入横评会让卡片无意义 |
| `getCityTagSignature` 的 boost 默认 1.5 | 不是 1.0 | 1.0 太宽松，任何"略高"都进；1.5 更接近"显著"语义 |
| 不打本地 cache | 每次 computed 重算 | 52 行 × 3 城，O(n)；后续如要 10000 行再加 memo |
| 走完整 importer / loader / seedSnapshot 链路 | 不直接 ad-hoc 解析 | 同步其它数据源的做法；未来如果加更多 csv 复用同链路 |

## 兼容性

- `DataSnapshot.listingTagSummaries` 是新字段，已有代码不读即不破坏
- snapshotLoader OPTIONAL 加载，缺 csv 不抛错
- importer 中旧输入字段无变化，远程 URL 模式不需升级
- 测试 `tests/buildIntegrity.test.ts` 已有 `listing_tags_summary.csv` 列名与 ≥10 个 tag 检查（v0.31.0 接入时就写了），本版本自然满足

## 已知边界

- 横评只支持三市（深圳 / 广州 / 珠海），未来扩展到第 4 城时：派生层无任何改动；UI 的 "三市标签" 字样要改为"多市"。
- `cityTagSignature` 的 otherAvg 仅对"在其他城市出现过"的标签有意义——仅本市的标签会被 continue 掉。
- 远程 csv 没更新端到端测试：因 snapshotLoader 靠 `downloadText` 拉，没法在 vitest 中模拟。本次接入只测"代码路径"，真实网络加载按 dynamic 路径在 dev 模式由 seedSnapshot 走 `?raw` 提供。
