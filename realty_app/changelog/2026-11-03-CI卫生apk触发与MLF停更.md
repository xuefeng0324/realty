# CI 卫生：apk 仅手动触发 + MLF 停更 + 仓库清理（2026-11-03，不发版）

仅 CI / 脚本 / 文档改动，按 VERSIONING.md 不 bump 版本。

## 背景与改动

1. **`apk-self-hosted.yml` 改为仅 `workflow_dispatch`**。
   自托管 runner 长期不在线，push 触发的 run 永远 queued，污染每个提交的
   checks 列表（每次发版都要解释一遍这个黄点）。移除 push 触发器与已失效的
   job 级 `if`（`APK_ENABLE` 变量开关随之作废）；有 runner 在线后想恢复
   push 触发，回退本文件触发器即可。
   **顺手修了一个潜伏 bug**：创建 Release 的步骤条件是
   `event_name == 'workflow_dispatch' || inputs.release == 'draft'`——
   仅手动触发后前半句恒真，`release: skip` 输入实际被忽略。改为
   `inputs.release != 'skip'`，恢复输入开关语义。
2. **`mlf` 停更**（上轮建议 3 的剩余项）。央行 MLF 栏目 2026 改版为
   「招标公告」，公告只有招标量/期限、没有中标利率，拿不到 `mlf_1y_pct`
   （2026-11 实测：46 个「中期借贷便利」标题全是招标公告，0 个结果公告）。
   处理与 zh-price-filing 一致：移出 P2 源清单并注释原因，CSV 保留
   last-good，前端照常渲染；`check-csv-freshness` 豁免名单同步加入
   `mlf_history.csv`（停更后数据固定变旧，不豁免会每周误报 STALE）。
3. **清理仓库根未跟踪垃圾**：误建的 `%TEMP%/` 目录（早期 probe 脚本与
   临时输出）+ 11 个一次性 `_probe_*.py` / `_add_publish_dates.py` /
   `_append_freshness.py` / `_diff_gd_after_gbk.py`。
   注意：`realty_app/changelog/2026-09-10-v1.122.25_post-fix_GBK_unlock_report.md`
   也是未跟踪文件，但它是 changelog 文档而非垃圾，保留未动——请确认是
   提交入库还是删除。

## 验证

- js-yaml 解析三个改动 workflow：通过；apk 触发器只剩 workflow_dispatch。
- 真实复验 MLF 栏目（2026-11-03 本机）：央行 MLF 专栏列表全是「招标公告」，
  无「开展情况」结果公告——停更判断成立。
- `npx vitest run tests/ciWorkflowContracts.test.ts tests/mlfHistory.test.ts`：
  见提交前记录（mlfHistory 读静态 CSV，不受停更影响）。
- `npm test` / `npm run type-check`：见提交前记录。
