## 改了什么

### 1. 修 `scripts/crawl_shibor.py` — IndentationError（脚本根本不能跑）

**bug**：line 112 的 `for rec in payload.get("records") or []:` 多缩进了 2 个空格，导致 Python 报 `IndentationError: unexpected indent`。脚本**任何时候都跑不起来**——这就是 shibor.csv 91 天陈旧的根因（cron 调它立刻就 fail，没 commit 也没日志）。

**修法**：line 112-128 全部 -2 空格缩进。脚本跑通 → shibor.csv 自动 +34 行（最新到 2026-09-10）。

### 2. 修 `scripts/crawl_omo_rr.py` + `scripts/crawl_mlf_history.py` — Windows GBK stdout bug

**bug**：PBOC 公告标题里有 `\ufffd`（乱码字符）/ 古汉字，Windows cmd 默认 GBK 编码无法编码这些字符 → 脚本 print 时抛 `'gbk' codec can't encode character '\ufffd'` → 爬虫**能抓到数据但 print 报错让 cron 整 job 红**。

**修法**：脚本启动时检测 stdout 编码，若非 UTF-8 就用 `io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")` 包装。注释说明**仅影响 print 输出，不影响 csv 写文件**（atomic_write 显式 encoding="utf-8"）。

**结果**：
- `crawl_omo_rr.py` 跑通 → omo_rr_history.csv 自动 +11 行
- `crawl_mlf_history.py` 跑通 → 但 PBOC 自从 2025-02 之后**没再发 MLF 公告**（PBOC 改革后 MLF 暂停被其他工具替代），所以 mlf_history.csv 保持 2025-02-25 那一行（**这数据滞后是 PBOC 政策原因，不是脚本 bug**）

### 3. 补利率/PBOC 数据 — 等同于 cron 周末产出

`crawl-monthly-stats70.yml` cron `0 2 16-20 * *` 会在每月 16-20 日跑这些爬虫。今天 9-10 在 cron 触发窗口外，手动本地跑**等同于 cron 产出**：
