# 房源筛选验收（LISTING_FILTER_ACCEPTANCE）

> 功能 ID：**F-LIST-01**（类型 / 装修专项）  
> 对照：贝壳/链家「在售 | 成交」切换；本仓种子 `listings.csv` 字段实际取值。  
> 总流程：[TEST_ACCEPTANCE.md](./TEST_ACCEPTANCE.md) · [FEATURE_QA_PROCESS.md](./FEATURE_QA_PROCESS.md)

---

## 1. 问题背景（2026-07-26 复盘）

| 现象 | 根因 |
|------|------|
| 选「在售」或「成交」后列表变空 | UI 传 `listingType=在售/成交`，种子全是 `listing_type=二手房`，**字面相等过滤 → 0** |
| 选部分「装修」像没数据 | 选项只有精装/简装/毛坯，样本大量是**豪装/普装**；简装仅约 13 条 |

**结论**：筛选验收必须断言「真实种子分布」，不能只测 mock 字符串相等。

---

## 2. 语义约定

| UI | 匹配的数据取值 | 种子现状（约） |
|----|----------------|----------------|
| 全部 | 不限 | ~1300 |
| 二手房 | 二手房、二手、在售… | ~980 |
| 新房 | 新房、新盘、期房… | ~320 |
| 成交 | 成交、已成交… | ≈0 |

实现：`src/local/listingFilterMatch.ts` → `filterListings`；数据脚本 `scripts/enrich_listing_type_new_used.py`。

---

## 3. 验收标准

### UI

| 期望 | 不期望 |
|------|--------|
| 类型：全部 / **二手房** / **新房** / 成交 可点（「在售」为二手房别名，见 listingFilterMatch） | 文档仍写「在售」导致手工验收对不上 |
| 装修含：不限、精装、豪装、普装、简装、毛坯 | 只有精装/简装/毛坯导致豪装无法选 |
| 0 套时 EmptyState 说明当前条件（含「成交几乎无样本」） | 空白列表无文案 |
| 列表卡片 `[data-listing-card]`：总价大字 + 单价 + 室卫·面积·朝向；挂牌 pill 与详情同源 | 仅一行灰字、只有评分优缺点、无单价 |
| 户型筛选与地图找房同档（不限/1/2/3/4室+，`bedroomBand`） | 仅地图能筛室数、列表不能 |
| 从地图带 `communityId`：显示「仅看小区」chip，可清除；重置一并清除 | 重置后仍锁单小区 |
| 关键字搜索框 `[data-listing-keyword] input` 占位文字垂直居中（`height`=`line-height`） | 文字顶偏/底偏 |

### 功能

| 期望 | 不期望 |
|------|--------|
| 深圳/广州选「在售」→ 有列表且 total>0 | 在售直接清空 |
| 选「成交」→ 允许 0，提示改回全部/在售 | 用户以为 App 坏了 |
| 选精装/豪装/普装/毛坯 → 各有命中 | 选豪装无入口或恒空 |
| 重置 → 恢复全市列表 | 重置后仍空 |

### 逻辑

| 期望 | 不期望 |
|------|--------|
| `matchesListingTypeFilter("二手房","在售")===true` | 仅 `===` 字面比较 |
| 「共 N 套」与 `filterListings.total` 一致 | 计数与列表脱节 |
| 在售+精装交叉 total>0（种子） | 组合条件无故归零 |
